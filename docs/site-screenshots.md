# Скриншоты VAP для сайта Vetro Studio (снятие и мокапы)

Сайт `https://phnem.github.io/Vetro-Studio/` (репозиторий `D:\AndroidStudioProjects\Vetro studio`, `github.com/Phnem/Vetro-Studio`)
показывает VAP на двух страницах: `index.html` (блок VAP) и `vap.html` (герой + галерея из четырёх экранов). Сейчас там
**заглушки**: слоты ждут реальных скриншотов. Достаточно положить четыре файла `assets/img/vap-*.webp` в репозиторий сайта, HTML
менять не нужно. Этот документ — как снять такие кадры, чтобы они выглядели как мокапы страницы Collection, и как проверить результат.

Проверено 2026-11-13 на Xiaomi 13 (`2211133C`, серийник `3871a9d6`, Android 16, экран 1080×2400, 440 dpi) и на сайте в состоянии
коммита `39ec0a5`. Что не проверено, помечено «не проверено».

## 1. Что нужно получить

| Файл | Где показывается | Что должно быть на экране |
|---|---|---|
| `vap-player.webp` | центр героя `vap.html` и `index.html`, карточка «Gestures and tracks» | плеер с видео и жестовыми/дорожечными элементами (alt на сайте: «VAP player with gesture controls») |
| `vap-library.webp` | левый телефон героя, карточка «Your library» | библиотека: папки и миниатюры видео («video library with folders and thumbnails») |
| `vap-subtitles.webp` | правый телефон героя, карточка «Subtitle tools» | редактор субтитров со сдвигом тайминга («subtitle editor with timing offsets») |
| `vap-ai.webp` | карточка «On-device AI» | генерация субтитров Whisper на устройстве («on-device Whisper subtitle generation») |

Формат: **WebP, 720×1560 (6:13)**, обычно 80–300 КБ (предел скрипта 350 КБ). Имена ровно такие: по ним сайт находит картинки сам.
Без файла слот остаётся заглушкой с логотипом VAP (так задумано: `site.js` убирает `<img>`, если файла нет), поэтому можно класть по одному кадру.

## 2. Как сайт оформляет скриншот (этого в кадре быть не должно)

Скриншот попадает в `.phone > .phone-screen.shot-slot > img` (`assets/css/site.css`, `vap.html`). Всё остальное рисует сайт:

- **рамка телефона** (`.phone`: тёмный корпус, боковые кнопки, тень): ширина задаётся `--w`, экран всегда `aspect-ratio: 360/780` (это 6:13);
- **«остров» камеры** (`.island`, чёрная пилюля сверху по центру, 31 % ширины) и **блик** (`.glare`, диагональный градиент) поверх картинки;
- **веер из трёх телефонов** в герое (`.cluster-hero`): левый −9°, правый +9°, центральный прямо, лёгкий параллакс от мыши и прокрутки;
- **стеклянные чипы** (`.float-chip`) вокруг телефонов: на `vap.html` «Media3», «ASS · SSA», «Whisper offline»;
- красный постерный фон, тикер и подписи.

Поэтому в кадре **только экран приложения**: без рамки, острова, теней, чужих подписей и картинки-мокапа. Картинка масштабируется
`object-fit: cover`, так что пропорция 6:13 обязательна, иначе края обрежутся.

**Как это сделано у Collection.** Страница `collection.html` скриншотов не использует: её телефоны наполняет `assets/js/screens.js`
(сгенерированный HTML/SVG экрана с «живым» поведением, часы всегда `9:41`, как на макетах App Store). Для VAP выбраны настоящие кадры:
под них и подготовлены слоты. Анимированные экраны как у Collection — отдельная задача в репозитории сайта (`screens.js`, `data-screen`
на `.phone`), а не снятие скринов.

## 3. Подготовка телефона и приложения

1. **Сборка.** `.\gradlew.bat :app:installFossDebug` (приложение `com.phnem.vap`, см. README, раздел сборки). Телефон по USB, отладка включена
   (`adb devices`).
2. **Язык интерфейса: английский** (картинки общие для EN и RU версий сайта, alt-тексты английские), **тема: тёмная** (под красный фон сайта
   и палитру Collection).
3. **Только синтетика, никаких личных данных.** Библиотека для кадров собирается из ваших сгенерированных клипов, а не из личных папок: в
   кадр не должны попасть имена файлов, пути, фото, чужие видео, аккаунты. `tools/prepare-video-fixtures.ps1` даёт сервисные «миры» 320×180
   для тестов (для витрины некрасиво). Для кадров сайта делайте клипы в палитре бренда, например (проверено, ffmpeg в `D:\ffmpeg\bin`):

   ```powershell
   $ff = 'D:\ffmpeg\bin\ffmpeg.exe'
   & $ff -y -f lavfi -i "gradients=s=1280x720:r=30:d=40:speed=0.02:c0=0xE85002:c1=0x1B1D21:c2=0xFFB067:nb_colors=3" `
         -f lavfi -i "sine=frequency=330:sample_rate=44100:duration=40" -c:v libx264 -preset veryfast -pix_fmt yuv420p -c:a aac -shortest "Sunset Drive.mp4"
   ```

   Меняйте цвета (`c0`..`c2`) и `speed`, называйте файлы красиво («Sunset Drive», «Night Train», «Ocean Loop»), раскладывайте по папкам
   (`adb push … /sdcard/Movies/VAP-Demo/Travel/`, затем `am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file://…`, как в
   `tools/prepare-library-fixtures.ps1`). Для кадра редактора нужен короткий `.srt` с нейтральным текстом.
4. **Телефон:** режим «Не беспокоить», экран не гаснет (`adb shell svc power stayon usb`, потом `svc power stayon false`), яркость высокая.
   Если снимок чёрный, экран спал: `adb shell input keyevent KEYCODE_WAKEUP` и свайп вверх `input swipe 540 2000 540 700`.

## 4. Снятие: `tools/site-shots.py`

Нужен Pillow (`pip install pillow`; проверено 12.2 с WebP). Скрипт ничего не ставит на телефон.

```powershell
python tools\site-shots.py begin                        # экран 1080x2340 (6:13) + демо-статусбар
# открыть на телефоне нужный экран (приложение перезапускается после смены размера!)
python tools\site-shots.py shot vap-library --fix-status 105
python tools\site-shots.py shot vap-player  --fix-status 105
python tools\site-shots.py end                          # ОБЯЗАТЕЛЬНО: вернуть размер экрана и статусбар
python tools\site-shots.py check                        # размеры, вес, какие имена ещё не сняты
```

Что происходит: `begin` ставит `wm size 1080x2340` (у родного 1080×2400 пропорция 9:20, и кадр пришлось бы срезать) и шлёт демо-режим
SystemUI; `shot` делает `adb exec-out screencap -p`, кладёт сырой PNG в `captures\site\raw\` (папка `captures/` в git игнорируется),
приводит к 6:13, масштабирует до 720×1560 и сохраняет `captures\site\<имя>.webp` (качество 88, `--quality` меняет); `end` делает
`wm size reset` и выходит из демо-режима. `convert <png> <имя>` только конвертирует готовый PNG (например, снятый на эмуляторе).

**Если `end` забыли.** Экран останется 1080×2340 с неродной разметкой: выполните `python tools\site-shots.py end` или
`adb shell wm size reset`. Команда безопасна для повторного запуска.

### Статусбар (9:41)

На макетах Collection часы везде `9:41`, батарея полная, без уведомлений. **На этом Xiaomi 13 демо-режим SystemUI не работает** (HyperOS
игнорирует `com.android.systemui.demo`: проверено, в кадре остаются реальное время и значок зарядки). Поэтому на телефоне снимайте с
`--fix-status 105`: скрипт закрашивает полосу статусбара копией соседней строки пикселей и рисует `9:41` слева и полную батарею справа.
Работает там, где под статусбаром ровный фон (тёмные экраны VAP); на пёстром фоне виден вертикальный шов. Тогда меняйте экран или снимайте
на эмуляторе Android Studio, где демо-режим работает штатно (эмулятор не проверялся). Высоту полосы (`105` — пиксели оригинала для этого
телефона) для другого телефона подберите по первому снимку в `captures\site\raw\`.

## 5. Проверка на сайте (до коммита)

1. Скопируйте `captures\site\vap-*.webp` в `D:\AndroidStudioProjects\Vetro studio\assets\img\`.
2. В репозитории сайта: `python -m http.server 3000`, откройте `http://localhost:3000/vap.html` и `http://localhost:3000/`.
3. Чек-лист:
   - в центре и по бокам героя картинки, а не логотип-заглушка; галерея ниже показывает все четыре кадра;
   - остров камеры не закрывает важное; часы `9:41` видны слева от него, батарея справа;
   - чипы («Media3», «ASS · SSA», «Whisper offline») не перекрывают главное на экране;
   - на ширине 375 px и на десктопе кадры чёткие, углы скруглены рамкой, без белых полос по краям;
   - во всех кадрах один язык, одна тема и одно время; нет личных данных, путей, уведомлений;
   - `python tools\site-shots.py check` не показывает `BAD`; суммарный вес четырёх файлов разумный (меньше 1 МБ).
4. Коммит и публикация файлов выполняются в репозитории сайта (там идёт отдельная работа над страницами: не переписывайте чужие правки,
   добавляйте только `assets/img/vap-*.webp`). Сырые PNG остаются в `captures/` VAP и в git не попадают.

## 6. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| снимок целиком чёрный (2 КБ) | телефон спит или экран заблокирован | `KEYCODE_WAKEUP`, свайп вверх, снять заново |
| кадр обрезан или с полосой | экран не 6:13 | `begin` не выполнялся или `end` уже вызван; `adb shell wm size` должен показывать Override 1080x2340 |
| приложение «поехало» после `begin` | смена размера пересоздаёт активность | откройте нужный экран после `begin` |
| время и батарея не 9:41 | оболочка игнорирует демо-режим | `--fix-status <px>` или эмулятор |
| файл тяжелее 350 КБ | много текстуры и шума на экране | `--quality 80`, упростить кадр (меньше миниатюр) |
| на сайте всё ещё заглушка | неверное имя или файл не в `assets/img/` | имя ровно `vap-player.webp` и т. д.; жёсткое обновление страницы (кэш) |
