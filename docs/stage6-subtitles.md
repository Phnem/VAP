# Этап 6.2 — текстовые субтитры

2026-10-20. Реализация VAP, независимо от исходной инвентаризации Vetro.

## Реализовано

- Встроенные дорожки Media3: выбор, отключение, предпочтительный язык. Выбор сохраняется по URI и применяется сервисом без зависимости от экрана.
- Импорт SRT, WebVTT, базового ASS/SSA через системный файловый диалог. Текст копируется в приватное хранилище; внешний файл не изменяется и постоянное разрешение на него не требуется. UTF-8, UTF-16 с BOM, fallback Windows-1251.
- Поиск одноимённых субтитров рядом с SAF-видео. Для видео из MediaStore можно выбрать его папку один раз: разрешение READ_MEDIA_VIDEO само по себе не даёт чтение соседних текстовых файлов.
- Извлечение встроенных текстовых дорожек средствами demuxer/парсеров Media3. Видео и аудио не декодируются. Полученную текстовую копию можно выбрать, редактировать и синхронизировать; bitmap-дорожки не превращаются в текст.
- Два языка: основной снизу и второй импортированный/извлечённый сверху. Слой SubtitleView не масштабируется жестами zoom/crop видео, остаётся в PiP.
- Размер, три системных семейства шрифтов, цвет, непрозрачность, фон, обводка, тень и положение.
- Сдвиг в миллисекундах и синхронизация по двум парам таймкодов (масштаб времени + смещение) для внешних/извлечённых дорожек. Прямой встроенный renderer сохраняет исходный тайминг; для его изменения доступно извлечение текста.
- Полный текст, поиск, переход к реплике с учётом синхронизации, Clipboard, изменение текста/начала/конца реплики. Запись приватной копии атомарная.
- Экспорт SRT/VTT через CreateDocument с корректными MIME; экспорт включает сдвиг и масштаб времени. Снимок экспорта хранится в cacheDir на время системного диалога, чтобы поворот не терял результат.

Файлы: `player/subtitles/*`, `SubtitleToolsDialog.kt`, `SubtitleOverlay.kt`, интеграция PlaybackService/PlayerScreen/Controls и Preferences DataStore. Новых APK-зависимостей в 6.2 нет. FFmpeg используется только для подготовки тестовых файлов на компьютере.

## Проверки

70 JVM-тестов проходят: новые проверки SRT/VTT/SSA, Unicode, ASS override-тегов, неправильных таймкодов, перекрытий, seek по индексу, двух точек синхронизации, экспорта и диапазонов настроек. Debug/release и lint проходят (0 ошибок).

Нативный набор `subtitles` на Xiaomi 13/API 36 проверяет реальные MKV/SRT, ru/en, сохранённый выбор и Off, извлечение обеих дорожек с PTS, Android-разбор ASS, два языка, задержку, seek из текста, вкладки оформления и тайминга, настоящий SAF-импорт и сохранение редактирования. Через настоящий CreateDocument создан SRT и прочитан его результат. Системный grant выбранной тестовой папки проверен поиском соседнего файла и автоматическим обнаружением при открытии SAF-видео.

При проверке обнаружены и устранены: добавление `.txt` системой при неверном MIME, ошибка ASS-регулярного выражения на Android ICU, недоступность текста native view для Accessibility. Таймкоды извлечённого MKV сверены с FFprobe: контейнер сдвинул начало на 23 мс из-за AAC preroll.

Скрипты: `tools/prepare-subtitle-fixtures.ps1` и `tools/test-playback-device.ps1 -Suite subtitles`. Подготовка использует двухминутный sample из плеерных проверок. Тестовые файлы находятся в собственной папке Download/VAP-Subtitle-Test; чужие файлы не удаляются.

## Границы

Сложная типографика, векторные рисунки, karaoke, анимации и исходные стили ASS относятся к 6.3/libass. В 6.2 ASS преобразуется в обычный текст. Bitmap-субтитры поддерживаются штатным renderer, но для текстового редактирования им нужен OCR из этапа 8. Нет обещания побайтово сохранить исходный ASS/VTT: экспорт — нормализованный SRT/VTT.

Импорт ограничен 5 МБ/50 000 реплик; извлечение имеет общий лимит текста и выполняется в IO с отменой при закрытии диалога. Очень большие файлы и удалённые providers требуют отдельных замеров. Другие версии Android и физические TV пока не проверены.
