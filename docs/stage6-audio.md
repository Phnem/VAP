# Этап 6.1 — аудио

Дата: 2026-10-20. Реализован первый блок этапа 6. Debug/release, 50 JVM-тестов и lint проходят; основные сценарии проверены на Xiaomi 13/API 36. Субтитры (6.2–6.4) в этот блок не входят.

## Реализация

Кнопка аудиодорожки открывает диалог с вкладками «Дорожки», «Звук», «Выход». Подписи переведены на русский и английский.

- Список показывает язык/название, кодек, каналы и частоту дискретизации. Неподдерживаемые дорожки видны, но не выбираются. Выбор сохраняется по URI и устойчивому ключу формата; «Автоматически» снимает ручной override. Фактически воспроизводимая дорожка отмечена отдельно.
- Предпочтительный язык задаётся кодом BCP 47 (например, `ru`, `en`, `ja`) для всех видео. Ручной выбор конкретного файла имеет приоритет. Настройки применяет сервис, поэтому переход к следующему файлу работает без открытого экрана. При отсутствии языка остаётся штатный подбор Media3.
- Внешний локальный звук выбирается через `OpenDocument`; право чтения сохраняется. Если установлен стандартный DocumentsUI, используется он: фирменное окно Xiaomi скрывает список файлов в landscape. На остальных системах остаётся обычное разрешение Intent. В манифесте добавлены только две точечные package queries для стандартного браузера документов, без новых разрешений. `AudioMediaSources` объединяет видео/текст основного источника и аудио внешнего через `MergingMediaSource`/`FilteringMediaSource`. Встроенный звук временно заменяется; кнопка возврата восстанавливает его. Позиция, очередь и play/pause сохраняются. Длительность основного видео не сокращается; короткая внешняя дорожка может закончиться раньше.
- Задержка от −2000 до +2000 мс, шаг интерфейса 10 мс: отрицательное значение отбрасывает начальные PCM-кадры, положительное добавляет тишину. Смена задержки переоткрывает текущую позицию с прежним намерением play/pause. Смещение заново применяется при перемотке/смене файла, но не накапливается при обычном flush Sonic для смены скорости.
- Сохранение высоты голоса включено по умолчанию: `pitch=1` при любой скорости, обработка Sonic Media3. При выключении pitch следует speed, в том числе при временном ускорении.
- Пять полос peaking EQ (100/300/1000/3000/10000 Hz), ±12 dB; усиление 0…12 dB; баланс −1…+1; смешивание стерео в моно. Баланс/моно не угадывают раскладку многоканального источника и работают только с двумя входными каналами.
- Автоматическое выравнивание — потоковый RMS-регулятор: цель 0.15, диапазон gain 0.25…4, плавная атака/восстановление, без усиления цифровой тишины. Это не анализ целого файла по LUFS/EBU R128. Выход ограничивается диапазоном PCM16; большое усиление/EQ может клиппировать пики.
- PCM16-процессор для 1…8 входных каналов включён всегда, float output, compressed passthrough и offload исключены из этого пути. Это обеспечивает применение обработки, но повышает нагрузку по сравнению с аппаратной передачей сжатого аудио; долгие замеры — этап 10.
- Вкладка выхода перечисляет системные output devices и отправляет `setPreferredAudioDevice`. Реальный маршрут определяет Android. При отключении выбранного устройства возвращается системный маршрут. ID устройств не сохраняются между запусками.
- Язык и сохранение pitch — глобальные настройки. Ручная дорожка, внешнее аудио, задержка, EQ, gain, баланс, mono и RMS — DataStore по URI. Ошибки записи показываются через существующий канал ViewModel.

Основные новые файлы: `player/audio/{AudioSettings,PlaybackAudioProcessor,AudioTracks,AudioMediaSources,AudioRuntime,AudioCommands}.kt`, `player/ui/AudioToolsDialog.kt`. Интеграция: `PlayerFactory`, `PlaybackService`, `PlayerScreen`, `PlayerControls`, `PlayerPreferences`, `PlaybackSettingsViewModel`, строки двух языков. Новых зависимостей нет.

Vetro не менялся. Прочитан существующий `media/ui/StreamPlayerActivity.kt` с применением preferred language; общий шаблон выбора через TrackSelectionParameters адаптирован к сервису VAP. DSP и объединение локальных источников написаны заново. GPL-исходники не использовались, FFmpeg присутствует только на компьютере для подготовки синтетических файлов.

## Проверки

50 JVM-тестов прошли (40 прежних + 10 DSP). Новые проверки: bit-exact нейтральный PCM, баланс, моно без переполнения, ограниченное усиление без wraparound, усиление центральной частоты EQ, сближение RMS тихого/громкого сигнала, цифровая тишина, многоканальный ввод, некорректные параметры, стабильность фильтра при низкой sample rate.

Новый набор `audio` на Xiaomi 13/API 36 прошёл: две реальные AAC-дорожки MKV, язык/ручной выбор/возврат к файлу без UI, реальные PCM-метрики баланса/gain/mono перед AudioTrack, точные PCM-вставка/отбрасывание для задержки, pitch-параметры, внешняя MKA/FLAC, восстановление встроенного звука, DataStore roundtrip, запрос системного выхода/отказ неизвестного ID и переподключение контроллера.

Набор `audio-ui` прошёл: нативное меню дорожек и языка, переключатель pitch, ползунки задержки/EQ, mono, список выходов, настоящий выбор MKA через SAF, постоянный grant, декодирование и возврат к embedded. Тест ждёт завершения системного поворота после пикера и прокручивает содержимое, а не нажимает координаты предыдущего окна. Просмотрены скриншоты меню и EQ.

Итого восемь наборов устройства прошли: `core`, `controls`, `ui`, `display`, `video`, `video-ui`, `audio`, `audio-ui`. Общий прогон прошёл первые семь; последний повторён отдельно после исправления синхронизации UI-теста с системным пикером. После заключительной правки жизненного цикла задержки повторно прошли `core` и `audio`: обычный flush при смене скорости не добавляет задержку повторно, явный reset для перемотки добавляет её снова.

Минифицированный release APK подписан стандартным локальным debug-ключом только для тестовой установки. Проверены две AAC-дорожки, подключение внешней MKA через настоящий DocumentsUI и French/FLAC в списке активных дорожек. После `am force-stop` и холодного запуска сессии внешний источник восстановился без повторного выбора файла. Усиление изменено до 5.86 dB; системная MediaSession показывает `PLAYING`, без ошибки. Проверены сброс звука и возврат к двум встроенным дорожкам. В журнале release-процесса нет Playback error, FATAL EXCEPTION, NoSuchFieldException или RejectedExecutionException.

Финальная сборка: `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `assembleRelease`, `lintDebug` — **BUILD SUCCESSFUL**, 50 тестов без ошибок/пропусков; lint — 0 ошибок, 44 предупреждения и одна подсказка. На телефон возвращена debug-сборка и открыт главный экран; воспроизведение поставлено на паузу. Системный таймаут экрана не менялся.

Локальные логи и снимки в игнорируемом `app/build/device-test/`: `stage61-final-build.log`, `stage61-all.log` (семь PASS и прежняя ошибка UI-теста), `stage61-audio.log`, `stage61-audio-ui.log`, `stage61-core-final.log`, `stage61-release-logcat.txt`, `audio-ui-*.png`. ## Границы

Проверяется цифровая обработка и работа реального декодера/сервиса на одном телефоне. Акустические измерения, субъективное качество, точный A/V lip-sync на разных скоростях, многоканальные HDMI-раскладки, Bluetooth и USB-ЦАП физически не проверены. Перечень устройств и preferred route не доказывают прохождение звука через каждый из них. API 26–35 и другие модели требуют отдельного прогона. Синтетические AAC/FLAC не покрывают все форматы внешнего аудио, DRM и сетевые live-потоки.

Для точных сигнатур использовалась версия из сборки, а не предположение о текущем SDK.
