# Этап 8.1 — локальные субтитры Whisper

Дата: 2026-10-21. Проверки на Xiaomi 13, Android 16. Модели не входят в APK, аудио не загружается в облако.

## Перенос и сборка

MIT Vetro AudioExtractor, LinearResampler, модельный каталог, идеи WhisperCppEngine и WhisperSubtitleManager адаптированы в `ai/whisper/`. Vetro остаётся неизменным. Добавлены корректный abort, освобождение контекста после задачи, ограничение очереди нативного рабочего потока, обычный UTF-8 в JNI, атомарный кэш и безопасная докачка. Android SpeechRecognizer из Vetro не переносился: его системный провайдер может отправлять звук в сеть.

whisper.cpp закреплён на `927cfce34f31707e17f2bff35c349632fb9e2c3a`; архив SHA-256 `41b664fee09e79176ac277b5237debec34f8d74af3c7d71f333f1ec67989ecde`. `tools/prepare-whisper-source.py` загружает исходники в build, проверяет хеш и отвергает ссылки/выход за каталог. Чистая сборка не зависит от файлов Vetro. CMake собирает CPU, без OpenMP, Vulkan, CUDA, BLAS, KleidiAI и загрузки исполняемых плагинов. Четыре ABI: arm64-v8a, armeabi-v7a, x86_64, x86. ARM64 — базовый armv8-a, без обязательного dotprod/fp16; x86 — без обязательных AVX/FMA. Ядра оптимизируются `-O3` и в debug: без этого первый тест оказался непригодно медленным.

Whisper и HarfBuzz используют один NDK 27 `libc++_shared`. Сравнены build-id, `.text` и `.rodata` упакованного runtime с runtime сборки субтитров; различается удалённая AGP отладочная информация. Все 64-битные ELF проверены на LOAD alignment ≥16 КБ; 32-битные библиотеки NDK имеют 4 КБ. Моделей `ggml-*.bin` в APK нет (`DebugProbesKt.bin` — небольшой ресурс coroutines, не модель).

## Обработка

Плеер → Субтитры → Whisper. `AudioExtractor` использует Media3 Transformer и тот же NetworkPlayback/AudioMediaSources для локальных URI, HLS/DASH и авторизованных источников; учитывает выбранную аудиодорожку и внешний аудиофайл. Видео удаляется из экспорта, PCM сводится в mono 16 кГц. Побочный AAC-файл удаляется. Один запрос ограничен фрагментом до 60 с и 61 с PCM; менеджер обрабатывает куски по 30 с. Не загружает целый фильм в память.

Сначала обрабатывается фрагмент текущей позиции, затем конец и начало видео. Допускается конечное видео до 24 ч; live/неизвестная длительность отклоняются. Язык auto определяется по первому фрагменту, далее фиксируется; доступен ручной код языка. Таймкоды сдвигаются на начало фрагмента и настроенную задержку звука. Показываются прогресс, язык и предупреждение, если обработка медленнее видео. Нативный контекст освобождается после каждого фрагмента; отмена вызывает whisper abort callback, затем рабочий поток освобождает память.

Ключ кэша включает URI, локальный stamp, длительность, выбранную/внешнюю дорожку, задержку, модель и язык. Атомарный JSON содержит готовые диапазоны и реплики. Отмена сохраняет завершённые куски. Ограничения: 40 000 реплик, 8 МБ на запись, 64 МБ совокупно. Кэш можно очистить. Для изменяемого сетевого URL без устойчивого stamp при замене содержимого требуется очистить кэш.

По завершении дорожка записывается через SubtitleStorage и выбирается в настройках этого видео. Она доступна в «Дорожки» и «Текст»; существующий редактор экспортирует SRT/VTT. Повторная обработка той же записи использует кэш и ту же дорожку. Оригинальные файлы не меняются.

## Фоновый режим

Запуск только из видимого приложения. Уведомление с отменой, `START_NOT_STICKY`, без автозапуска после перезагрузки/уничтожения процесса. Загрузка использует `dataSync`, обработка на Android 15+ — `mediaProcessing`, на старых Android — `dataSync` для локальной обработки файла. При первом запуске задачи на Android 13+ UI запрашивает уведомления; отказ не запрещает саму обработку.

Core 1.15 отбрасывает новый mediaProcessing bit в ServiceCompat: на API 35+ используется прямой трёхаргументный startForeground. Обрабатывается системный onTimeout с отменой и stopSelf. Собственный предел на старых Android — 5 ч 45 мин. Частичный wake lock ограничен шестью часами и освобождается при закрытии сервиса. Готовые фрагменты остаются в кэше, незавершённый фрагмент пересчитывается. Это управляемая фоновая задача, а не обещание обходить ограничения Android/OEM.

## Проверки

`python tools/prepare-whisper-fixtures.py`, `tools/test-playback-device.ps1 -SamplePath app/build/device-test/sample.mp4 -Suite whisper`. Тестовые веса и JFK WAV закреплены по SHA-256, не включаются в приложение.

Xiaomi: настоящий CPU inference tiny, язык en, осмысленный текст с ask/country, таймкоды, progress, отмена и последующий повторный inference PASS. 11 с речи занимают примерно 1,9 с на этом телефоне (без обещаний такой скорости для других устройств/моделей). Transformer PCM, докачка первых 1 МБ до полного файла, реальный SHA-256 32 МБ, удаление модели, Unicode atomic cache, подключение дорожки, SRT/VTT round-trip и cached retry PASS. Проверены настоящий foreground service, завершение после HOME и освобождение сервиса. Обычная панель открыта через accessibility; просмотрены скриншоты моделей и действий после прокрутки.

MP4 с двумя дорожками (тон по умолчанию, речь выбрана отдельно) успешно распознан: проверяется именно выбранная дорожка. Обе минифицированные release-сборки собраны и установлены на телефон; отдельный Java runner действительно вызвал JNI и распознал JFK, проверил callback ABI, Cast metadata/options и отсутствие Google Cast в FOSS. 118 JVM PASS; lint FOSS 0 ошибок / 74 предупреждения, Cast 0 / 73. Регрессии core, ass и casting PASS; libass p95 простой сцены 1018 мкс. Логи — `whisper-video-device.log`, `whisper-release-build.log`, `whisper-release-{foss,cast}-smoke.log`, `whisper-regression-{core,ass,casting}.log` в build/device-test. Обычный runner восстановлен, на телефоне FOSS debug. Длинные фильмы, другие языки/устройства, base/small, длительное screen-off/Doze и тепловой режим не измерены.

## Live Subtitles

Исследован официальный пример whisper-stream: окно звука и повторный inference с перекрытием. Для звука плеера нужен декодированный PCM tap, согласование с seek/скоростью/сменой дорожки, устранение повторов в перекрытии и ограничение нагрузки. Системный захват микрофона не заменяет обработку дорожки видео. Текущий механизм работает фрагментами для конечного видео; потоковые live-субтитры не реализованы. Пункт 8.1 требует исследование, а не выдачу пакетной обработки за live.
