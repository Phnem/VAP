# Этап 5.3 — декодеры, изображение и экспорт

Дата: 2026-10-20. Раздел 5.3 реализован; debug/release, 40 JVM-тестов, lint и шесть наборов проверок Xiaomi 13/API 36 прошли. Минифицированная release-сборка отдельно проверена на телефоне.

## Что доступно

В настройках плеера появился пункт **«Инструменты видео»**, с вкладками «Изображение», «Экспорт», «Информация о видео». Подписи есть на русском и английском.

- **Auto / HW / SW** выбирают видеодекодер. Auto предпочитает аппаратные реализации, SW использует программные MediaCodec, установленные Android. Это не встроенный FFmpeg и не обещание любого кодека на любом телефоне. HW/SW не подменяются молча друг другом при явном выборе.
- При ошибке инициализации Media3 пробует следующий доступный декодер. При ошибке уже работающего видеодекодера VAP исключает его, сохраняет очередь, позицию и намерение play/pause и пробует другой. Бюджет — до трёх исключений на элемент очереди. Ошибки контейнера/чтения не запускают цикл переключения кодеков.
- Ошибка остаётся доступной для диагностики. Можно повторить открытие, выбрать другой декодер или перейти к следующему файлу. Неподдерживаемая видеодорожка не выдаётся за успешно показанное видео, даже если аудио доступно.
- **HDR Auto** сохраняет штатный HDR-вывод на поддерживаемой поверхности. Переключатель SDR запрашивает GL tone mapping на Android 10/API 29+. Цветокоррекция HDR тоже использует SDR-вывод. На старых API коррекция HDR отключена.
- **Подбирать частоту дисплея** управляет `VIDEO_CHANGE_FRAME_RATE_STRATEGY_ONLY_IF_SEAMLESS`. Media3 передаёт кадровую частоту в Surface; окончательное решение принимает Android/прошивка. Приложение не меняет системные настройки частоты. Панель отдельно показывает FPS файла и текущую частоту дисплея; неизвестный FPS остаётся «—».
- Яркость **видеокадра**, контраст, насыщенность и гамма обрабатываются GPU. Это не яркость окна из вертикального жеста. Значения сохраняются по URI; есть сброс. Изменения ползунка применяются после отпускания и видны также на паузе.
- **Снимок кадра** использует PixelCopy поверхности видео: без доков, меню, субтитров интерфейса, экранного Fit/Crop/зума. PNG ограничен 4096 пикселями по большей стороне и содержит текущую цветокоррекцию.
- **MP4** экспортирует выбранный диапазон до двух минут, с высотой 720 px, H.264/AAC. На API 29+ HDR преобразуется в SDR. Цветокоррекция применяется, экранное кадрирование не применяется.
- **GIF** экспортирует до 15 секунд, до 480 px по большей стороне, 8 кадров/с, без звука, с фиксированной палитрой RGB332. Кадры извлекаются последовательно, не копятся в памяти. Это небольшой встроенный GIF89a/LZW-кодер, без стороннего нативного модуля.
- Во время работы виден прогресс, есть отмена. Незавершённые временные экспорты удаляются. Готовый результат сохраняется через системный **«Сохранить как…»**, без разрешения на всё хранилище. Отмена выбора места сохраняет подготовленный результат для повторной попытки. Задание живёт, пока жив ViewModel экрана плеера; закрытие Activity отменяет его.

Границы диапазона вводятся в секундах, `мм:сс` или `чч:мм:сс`. Проверяются порядок, длительность и нахождение внутри видео. Экспорт этого блока предназначен для локальных `file://` и `content://`.

## Реализация

`DecoderPolicy` фильтрует платформенные MediaCodec по аппаратным/программным признакам и исключённым именам. `DecoderRuntime` слушает реальные события AnalyticsListener, предоставляет имя активного декодера, формат, FPS, битрейт, HDR, dropped frames, последние ошибки и число восстановлений. Небольшие команды `VIDEO_INFO` и `VIDEO_RETRY` MediaSession доступны только UID и пакету самого приложения; внешние системные контроллеры сохраняют стандартное управление.

Общие параметры декодера/HDR/частоты и четыре параметра изображения хранятся в существующем DataStore. Сервис объединяет настройки текущего файла с общими. Экспорт создаёт собственные эффекты и собственный Transformer, без передачи GL-объектов работающего плеера между потоками.

`PictureEffect` преобразует linear RGB в электрический RGB, применяет насыщенность, контраст, яркость и гамму, затем возвращает linear RGB. Рабочее пространство Media3 явно задано как linear, чтобы не зависеть от изменившегося значения по умолчанию в библиотеке. GIF применяет соответствующее преобразование к SDR-пикселям Android.

Поверхность PlayerView теперь измеряется с пропорциями вписанного исходного видео. Масштабирование до выбранного режима выполняется снаружи; это одинаково работает для raw MediaCodec и GL-вывода. Неизвестный размер в момент замены декодера не сбрасывает пропорции. Эти изменения исправили обнаруженные телефоном лишние поля и неверные размеры после включения эффектов.

**Особенность Media3 1.11.1:** публичного управления playback tone mapping в обычном ExoPlayer недостаточно. В `PlayerFactory.VapVideoRenderer` изолирован адаптер к `PlaybackVideoGraphWrapper`, помеченному библиотекой как restricted. Там же при reset освобождается свой граф и очищается приватное поле `videoSink`, иначе библиотека повторно обращается к уже освобождённому GL executor. Для поля есть точечное R8 keep-правило, а `RestrictedApi` подавлен только у этого адаптера с объяснением. Версия Media3 закреплена; при её обновлении этот контракт и minified smoke-тест обязательны. Глобальный lint baseline не добавлялся.

Прочитаны MIT-исходники Vetro `media/subtitles/whisper/AudioExtractor.kt` и `media/player/StreamingPlaybackDiagnostics.kt`: переиспользован подход Transformer с Looper и отменой; сетевые диагностические метки не переносились в локальный плеер. Vetro не менялся, GPL-код не использовался.

Контракты библиотек проверены по локальным source JAR **1.11.1** и официальным материалам: [ExoPlayer](https://developer.android.com/reference/androidx/media3/exoplayer/ExoPlayer), [Media3 Transformer](https://developer.android.com/media/media3/transformer/getting-started), [HDR/tone mapping](https://developer.android.com/media/media3/transformer/tone-mapping), [SurfaceView](https://developer.android.com/media/media3/ui/surface).

## Проверки

Новые JVM-тесты проверяют диапазоны, ограничения/нечисловые значения параметров, цветокоррекцию, бюджет восстановлений и GIF. Для GIF используется независимый декодер JDK ImageIO: проверяются два кадра, цвета и переходы через CLEAR-коды и границы блоков. Всего JVM-тестов — **40**.

`tools/prepare-video-fixtures.ps1` создаёт короткие синтетические файлы локальным FFmpeg **на компьютере**. Бинарник в приложение не включён. `video` использует настоящие кодеки Xiaomi 13/API 36:

| Образец | Наблюдавшийся декодер |
|---|---|
| MP4, H.264, 23.976 и 60 FPS | `c2.qti.avc.decoder` |
| MKV, H.264/AAC | `c2.qti.avc.decoder` |
| AVI, MPEG-4/MP3 | `c2.android.mpeg4.decoder` |
| WebM, VP9/Opus | `c2.qti.vp9.decoder` |
| MP4, HEVC, 25 FPS | `c2.qti.hevc.decoder` |
| MP4, AV1, 30 FPS | `c2.qti.av1.decoder` |
| HEVC Main10/PQ/BT.2020 | `c2.qti.hevc.decoder`, HDR-метаданные подтверждены |
| Явный SW для H.264 | `c2.android.avc.decoder` |

В тесте восстановления адаптер **намеренно освобождает настоящий работающий HW MediaCodec** перед очередной подачей данных. Оба аппаратных AVC-декодера дают нативную ошибку, после чего продолжается воспроизведение на `c2.android.avc.decoder`. Это контролируемая инъекция отказа, а не утверждение о дефекте Qualcomm.

Проверяются MP4 с диапазоном 5–7 с, длительность, кадр и наличие H.264/AAC; GIF с длительностью 1 с декодируется Android; HDR-фрагмент экспортируется в H.264 с SDR transfer. Повреждённый и обрезанный пополам MP4 дают ограниченный исход/ошибку, не цикл повторов; следующий исправный файл воспроизводится.

`video-ui` использует реальные касания и PixelCopy: информация о декодере, изменение реальных пикселей яркостью на паузе, отсутствие белой кнопки Play в PNG, копирование результата, отмена GIF с удалением частичного файла, MP4 из меню, открытие/отмена настоящего системного выбора файла, HDR и SDR на SurfaceView. Проверяется применение переключателя частоты, а не обещается принудительная смена физического режима дисплея вопреки политике ОС.

Финальные результаты:

- `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `assembleRelease`, `lintDebug`: **BUILD SUCCESSFUL**; 40 JVM-тестов, 0 ошибок lint (42 предупреждения и одна подсказка).
- `core`, `controls`, `ui`, `display` прошли в общем прогоне; после исправления гонки освобождения кодека повторно прошли `video` и `video-ui`. Восстановление теперь берёт имя отказавшего кодека из исключения Media3, поскольку событие release может прийти раньше ошибки. Проверка реально привела к двум сбоям HW и продолжению через `c2.android.avc.decoder`.
- Независимый host ffprobe: MP4 H.264/AAC 1280×720, 2.012426 с, BT.709; HDR→SDR MP4 1.001 с, BT.709; GIF 480×270, 8 кадров, 1.000 с. Просмотрены PNG с цветокоррекцией и скриншоты вкладок.
- Минифицированный release APK подписан стандартным локальным debug-ключом только для установки тестовой копии. В нём выполнены запуск видео, включение/выключение SDR-вывода, изменение яркости GPU и PixelCopy. Через настоящий DocumentsUI успешно сохранён `Download/VAP-stage53-release-test.png`; файл извлечён и проверен: 320×180, цветное изображение без интерфейса. Это также проверяет R8 keep для внутреннего поля `videoSink`; в журнале нет Playback error, FATAL EXCEPTION, NoSuchFieldException или RejectedExecutionException.
- После smoke-проверки цветокоррекция тестового файла сброшена, принудительный SDR выключен; на телефон возвращена debug-сборка, открыт главный экран. Системный таймаут экрана не менялся.

Локальные логи и артефакты находятся в игнорируемом `app/build/device-test/`: `stage53-build.log`, `stage53-all.log` (первые четыре набора и исходная ошибка восстановления), `stage53-video.log`, `stage53-video-ui.log`, `stage53-release-logcat.txt`, `release-saved.png`, `clip.mp4`, `clip.gif`, `hdr-sdr.mp4`.

Повторение:

```powershell
$env:JAVA_HOME = 'D:\Android1\Android Studio\jbr'
.\tools\prepare-video-fixtures.ps1
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:assembleRelease :app:lintDebug --console=plain
.\tools\test-playback-device.ps1 -SamplePath 'D:\AndroidStudioProjects\VAP\app\build\device-test\sample.mp4' -Suite all
```

`all` включает шесть наборов: core, controls, ui, display, video, video-ui. Перед UI-тестами телефон пробуждается и разблокируется; его системный десятиминутный таймаут не меняется. Проверки заменяют активную очередь тестовыми файлами; настройки восстанавливаются при штатном завершении.

## Границы

Проверена одна модель телефона и перечисленные синтетические файлы. Это не сертификация всех вариантов AVI/MKV, Dolby Vision, HDR10+, HLG или цветопередачи экрана. HDR-проверка подтверждает PQ-декодирование, работающий вывод и SDR-экспорт, не калибровку яркости/цвета. Набор кодеков зависит от Android; дополнительных libvpx/dav1d/FFmpeg-модулей нет. GIF получает SDR-кадры от MediaMetadataRetriever, качество преобразования HDR зависит от платформы. На API 26 GIF свыше 4K отклоняется, поскольку уменьшенное извлечение кадра появилось на API 27.

API 26–35, другие GPU/прошивки, VFR-длинные файлы, 4K/8K-длительная нагрузка и нехватка диска требуют расширенного тестирования этапа 10. Звонки и физические аудиоустройства из 5.1 всё ещё не проверены. Этап 6 в этой работе не начинался.
