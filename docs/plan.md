## Аудит этапов 4–8.2, переработка интерфейса и 8.3 (2026-10-21)

Проверены код, нативный слой, документы и тесты этапов 4–8.2. Найдено и исправлено:

- Файл `vap` в корне проекта — PKCS#12-хранилище ключа (вероятно, подпись релиза) — не игнорировался git. Добавлены `/vap`, `*.p12`, `*.pfx` в `.gitignore`; сам файл не тронут. В репозитории пока нет ни одного коммита.
- Экспорт SRT экранировал `&`, `<`, `>` как HTML-сущности (в других плеерах «&amp;»): теперь сущности только в WebVTT и во внутренней копии.
- Облачный перевод обрывался на 15 с и сообщал «ошибка чтения аудио»: тайм-аут чтения 90 с, один POST без повторов, как и прежде.
- NPE в автопоиске субтитров, если провайдер не вернул имя файла.
- Подписи действий PiP были только на английском; окно всегда 16:9, теперь пропорции видео в пределах Android.
- Панели Whisper, перевода и Smart Sync показывали ошибки и язык чужой задачи (общее состояние `AiRuntime`).
- Блок ошибки воспроизведения перекрывал центральную кнопку Play.
- `tools/test-playback-device.ps1` не работал на Windows PowerShell 5.1; подключён набор `sync`.
- Удалены неиспользуемые ресурсы (2 иконки, 2 строки); в матрице глубина SAF-обхода 6, а не 4.

Переработка интерфейса по указанию владельца — `ui-kit.md`: шторки Collection вместо Material 3 для настроек, звука, видео, субтитров (Whisper, перевод, Smart Sync, OpenSubtitles), трансляции, сетевых источников, таймкода, режима кадра, ориентации и предложения продолжить просмотр. Проверка на устройстве выявила и устранила дефекты новой вёрстки: схлопывание таймкода при клавиатуре в альбомной ориентации, нерабочая вертикальная прокрутка над ползунком, вкладка «Текст», съедавшая всю шторку, кнопки правки реплики вне экрана, потеря решения «позже» при пересоздании экрана, строка состояния поверх шторки, перекрытие шторки доком.

8.3 Smart Sync закончен и подключён к проверкам (`stage8-sync.md`): на реальных словах Whisper Tiny найден сдвиг −3000 мс.

Проверки: 130 JVM PASS; Xiaomi 13 — наборы `core`, `controls`, `ui`, `display`, `video`, `video-ui`, `audio`, `audio-ui`, `subtitles`, `resume`, `ass`, `online`, `network`, `servers`, `casting`, `whisper`, `sync`, `translation`, `library` PASS (`online` один раз из четырёх упал на гонке панелей управления до открытия шторки, два повтора PASS). Release foss/cast собираются (unsigned 44 434 122 / 45 306 327 байт), lint 0 ошибок (73/72 предупреждения). Минифицированный smoke-раннер после переработки интерфейса не запускался.

Выявлено, не исправлено: сообщения об ошибках из исключений (`AiRuntime`, диалоги) остаются английскими в русском интерфейсе; `ScopedNetworkAuth` расшифровывает хранилище на каждый запрос (стоит кэшировать); кэш сканирования читается на главном потоке при создании `LibraryViewModel`; PiP без `setAutoEnterEnabled`/`sourceRectHint` (предупреждение lint); светлая тема шторок визуально проверена на сетевых источниках и предложении продолжить.

## Принятые решения

- `applicationId = namespace = com.phnem.vap`.
- Лицензия приложения — MIT. Чужой GPL-код не копируется, используется метод clean room.
- Две сборки: `foss` без Google SDK (DLNA) и `cast` с Google Cast; тяжёлые модели загружаются отдельно.
- Один модуль `:app`; выделение `:player-core` пересматривается перед Этапом 9.
- Код Vetro копируется, Vetro не меняется.
- Русский и английский с первого дня; аниме-пропуск в VAP не нужен.
- Автоматическая видеотека после системного разрешения обязательна при первом запуске; SAF — дополнительный способ доступа. По умолчанию больше видео в папке означает более высокую позицию.
- Продолжать весь план по порядку, закрывая обнаруженные пробелы прежних этапов; внешнее оборудование и публикация считаются проверенными только при наличии результата.
- Дизайн: решения №1–9 в `design-spec.md` §12. Дизайн берётся напрямую из Vetro Collection (компоненты, анимации, поведение), отличается только палитра VAP; Collection не изменяется. Панели плеера, сети и трансляции — шторки Collection (`ui-kit.md`), без Material 3.

# VAP — Vetro Android Player
## План разработки и техническое задание

**Название:** VAP (Vetro Android Player)  
**Платформа:** Android  
**Папка проекта:** `D:\AndroidStudioProjects\VAP`  
**Исходный проект:** Vetro Collection  
**Основной референс кода:** https://github.com/anilbeesetti/nextplayer

### Общие требования

- Разработать самостоятельное Android-приложение для воспроизведения видео.
- Максимально переиспользовать готовый код Vetro Collection.
- Сохранить основные дизайн-концепции Vetro, анимации и стеклянные элементы интерфейса.
- Поддерживать локальные видео, сетевые источники и расширенные инструменты работы с контентом.
- Реализовать ИИ-функциональность преимущественно локально, с возможностью подключения облачных моделей.
- Обеспечить высокую производительность, плавность интерфейса и минимальное энергопотребление.
- Не перегружать интерфейс редко используемыми функциями.
- Вести поэтапную разработку с проверкой работоспособности после каждого этапа.

# Правила работы ИИ-агента

1. **Не начинать разработку с нуля**, пока не изучен соответствующий код Vetro Collection.
2. **На этапе 1 обязательно составить полную матрицу функциональности**, охватывающую все требования плана. Отдельно показать уже реализованные функции, частичные реализации и полностью отсутствующие возможности.
3. Переносить существующие компоненты только копированием, сохраняя исходный проект.
4. При миграции сначала добиваться функциональной эквивалентности, затем проводить рефакторинг.
5. Не предполагать наличие возможностей без проверки исходников.
6. Не создавать собственную реализацию возможности, если в Vetro уже есть подходящая и работоспособная.
7. До создания нового интерфейса изучить все предоставленные визуальные референсы.
8. Не принимать технические решения только ради сходства с Next Player — VAP является самостоятельным проектом.
9. Проверять лицензии до включения стороннего кода и бинарных библиотек.
10. Не добавлять заведомо тяжёлые библиотеки в базовую сборку, если их можно подключать опционально.
11. После каждого этапа проверять сборку и основные сценарии использования.
12. Не оставлять неработающие кнопки и декоративные элементы, выдаваемые за реализованные функции.
13. Сохранять актуальную документацию и отмечать изменения статусов функций.
14. Не переходить к следующему этапу, пока не выполнены обязательные критерии текущего.
15. Любые существенные изменения архитектуры документировать с указанием причин.

## Отчётность после каждого этапа

ИИ-агент должен предоставлять краткий отчёт:

- Что сделано.
- Какие конкретные файлы изменены.
- Что перенесено из Vetro Collection.
- Какие функции уже работают.
- Какие функции остались нереализованными.
- Какие обнаружены ошибки и ограничения.
- Какие проверки и тесты проведены.
- Что необходимо выполнить на следующем этапе.

**Критерий завершения всего проекта:** VAP представляет собой полностью автономное, стабильное Android-приложение с собственной библиотекой, полноценным видеоплеером, проработанным интерфейсом в стиле Vetro и модульными дополнительными возможностями, включая ИИ-инструменты.

## Производительность сетки библиотеки (2026-10-21)

Жалоба владельца: «лагает просто жесть». Замер на Samsung SM-S936B (120 Гц), release, прокрутка сетки
папок (`dumpsys gfxinfo` + atrace):

| | До | После |
|---|---|---|
| медиана кадра | 46 мс | 12 мс |
| рваных кадров | 86 % | 4 % |
| режим «Список» (для сравнения) | 7 мс, 1,5 % | — |
| внутри папки | — | 7 мс, 1,5 % |

Причина: `frostedGlass` с `layerBackdrop` на каждой карточке папки (design-spec §10, риск №1 сбылся).
UI-поток был свободен (композиция 70 мс на 131 кадр), RenderThread тратил ~12 мс на кадр на слои:
около 35 выделений видеопамяти и 820 заливок на кадр.

Исправление: размытое «просвечивание» листов считается один раз в картинку 1/6 размера
(`ui/library/FolderPlateBlur.kt`: листы, три прохода коробочного размытия, кеш 4 МБ), пластина рисует
эту картинку плюс тинт, кант и блик обычными заливками. Живых слоёв на карточке нет. Правило:
**не ставить `layerBackdrop` + размытие на элементы прокручиваемого списка.**

Остаточное: при появлении элементов управления плеера 16 % кадров не укладываются в 8,3 мс
(медиана 6 мс, p99 18 мс); не профилировано. Инструментальные тесты на этом телефоне не гонял:
они ставят debug-сборку с другой подписью и стёрли бы данные установленного release.

## Исправления по замечаниям владельца (2026-10-21, вторая партия)

1. **Обложки перерисовывались при возврате.** Кэш миниатюр был 24 МБ при ~0,5 МБ на кадр: в папке на
   60+ видео кадры вытеснялись и доставались заново через `MediaMetadataRetriever`. Теперь кэш в
   памяти — 1/8 кучи (32–128 МБ), плюс дисковый JPEG-кэш в `cacheDir/thumbs` (96 МБ, SHA-1 от ключа) и
   синхронное чтение из памяти (`peekVideoFrame`, `FolderPlateBlur.peek`), чтобы первый кадр не пустой.
2. **Мини-плеер: чёрный текст по чёрному.** Вне `Surface` цвет содержимого Material чёрный; теперь
   `onBackground`.
3. **Чёрная подложка под мини-плеером** и 4. **«плоское» стекло.** Слой содержимого укорачивался на 128 dp
   при активном плеере, и под доком оставалась пустота. Теперь слой на весь экран, а отступ списка берётся
   из `LocalLibraryBottomInset` (128 dp, с плеером 200 dp). Стекло показывает размытое содержимое.
5. **Листы-копии зависали поверх прокрутки.** `FlyingPapers` жил, пока папка открыта; теперь только пока
   идёт переход (`FolderMorph.flying`).
6. **Лаг открытия плеера.** По умолчанию плеер принудительно в альбомной ориентации, и экран разворачивался
   после первого кадра. `PlayerActivity` в манифесте получил `screenOrientation="sensorLandscape"`,
   настройка пользователя применяется по-прежнему. 99-й перцентиль кадра при открытии: 65–125 мс → 30–38 мс.
   Остаётся серия композиций по 13–20 мс в первые 300 мс (без трассировки Compose не профилировано).
7. **Меню слишком прозрачные.** `GlassSheet` теперь шторка `VapSheet` (почти непрозрачная, как в Collection).
8. **Поиск.** Поле было первым элементом списка. Теперь плавающая стеклянная строка `LibrarySearchBar`: над
   доком, при клавиатуре — над клавиатурой; док и мини-плеер под клавиатурой прозрачны, но остаются в
   композиции; списки сужаются через `imePadding`.
9. **Закрытие папки летело в ту же сторону, что и открытие.** В `collapse()` концы `from`/`to` были
   переставлены при прогрессе 1→0. Теперь концы те же, что при открытии.

Не проверено: инструментальные тесты (телефон владельца — release с другой подписью, они бы стёрли
данные); светлая тема проверена только на главном экране.
