# Этап 6.3 — libass

2026-10-20. Нативный backend написан для VAP. В исходном аудите Vetro libass отсутствовал; исходники Next Player не использовались.

## Реализация

libass 0.17.5, FreeType 2.15.0, HarfBuzz 13.0.1 и FriBidi 1.0.17 собираются из закреплённых исходников для четырёх ABI. JNI — собственный `app/src/main/cpp/ass_jni.c`, Kotlin API — `AssNative.kt`. Лицензии, хэши, особенности cross-build и воспроизведение сборки описаны в `subtitle-native-build.md`. FriBidi остаётся отдельной динамической библиотекой.

Импорт ASS/SSA сохраняет исходный документ и отдельную нормализованную текстовую копию. libass отвечает за стили, позиционирование, преобразования, fade, karaoke, векторные рисунки, shaping и bidi. JNI композитит изображения в premultiplied RGBA, публикуя новые bitmap только при изменении кадра.

При выборе встроенной ASS-дорожки VAP автоматически извлекает её исходный заголовок и события через Media3, сохраняя оформление. Вложения шрифтов Matroska читаются отдельным ограниченным EBML-reader: кластеры видео пропускаются seek, шрифты копируются в приватное хранилище. Исходный файл не изменяется. Во время подготовки Media3 продолжает воспроизведение; затем включается libass. Результат кэшируется по URI/дорожке с проверкой размера и времени изменения видео. Смена файла отменяет подготовку.

Рендер выполняется вне UI-потока, с частотой до 30 кадров/с и растром до 1920×1080. Кадр привязан к геометрии видео и его zoom/pan, SRT второго языка остаётся отдельным слоем. Уход Activity ниже STARTED освобождает нативное состояние; PiP продолжает отображение. Пользователь может отключить исходное оформление и настроить обычный текст. После редактирования текстовой копии её исходное ASS-оформление отключается для этой копии.

## Проверки

- Debug/release, четыре ABI, 71 JVM-тест, lint: успешно, ошибок lint нет.
- Xiaomi 13/API 36, набор `ass`: реальные пиксели libass, положение, move, transform, fade, повторный кадр без нового bitmap, исчезновение и перемотка назад.
- Исходный ASS извлечён из MKV; сохранены стили, теги и тайминг. Прочитано вложение шрифта с уникальным семейством VAPFixture; отличие ширины глифов подтвердило использование вложенного шрифта вместо системного Roboto.
- В UI одновременно показаны исходное жёлтое оформление ASS и второй SRT-язык. Автоматическая подготовка встроенной ASS и инвалидация кэша после изменения файла проверены.
- Karaoke проверен по изменению числа пикселей основного/вторичного цвета, векторный рисунок — по размеру реального bitmap.
- p95 тестовой сцены при 1080p — около 0,9–1 мс. Это измерение конкретной сцены, не гарантия для любых ASS-скриптов.
- В release APK представлены arm64-v8a, armeabi-v7a, x86_64 и x86. Все проверенные 64-битные ELF имеют выравнивание LOAD не меньше 16384; телефон с 16-КБ страницами отдельно не проверен.
- Минифицированный release установлен на Xiaomi 13: сохранённый встроенный ASS восстановлен после холодного запуска и отрисован с вложенным шрифтом. JNI/R8 не вызвали ошибок. Zipalign с параметром -P 16 прошёл; после smoke на телефон возвращена debug-сборка.

Сборка и нативный тест на других ABI/устройствах пока не запускались. Полный набор сложных аниме-скриптов, длительные сессии, энергопотребление, HDR-цвета субтитров и редкие варианты контейнера остаются проверками этапа 10. Подготовка больших встроенных ASS читает контейнер в фоне один раз; её стоимость на больших файлах нужно измерить. Времена ASS имеют точность до сотой секунды; при восстановлении контейнерного PTS округление не превышает 5 мс.
