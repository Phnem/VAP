# Замер плавности открытия папки на реальном телефоне

Только чтение: ничего не ставится, нажатия на экран делаете вы сами. Скрипт пропускает через белый список
только `getprop`, `dumpsys`, `pidof`, `atrace`, `pm path` и копирование APK приложения с телефона на ПК. Любая
другая команда `adb` отклоняется. Единственный «побочный эффект» — `dumpsys gfxinfo com.phnem.vap reset`:
он обнуляет счётчики кадров приложения в памяти (данные приложения не трогаются).

## Подготовка (один раз)
1. Основной телефон R5CY82VT33X: Настройки → Для разработчиков → **Отладка по USB**; подключите кабелем,
   на телефоне подтвердите отладку для этого компьютера.
2. Желательно, чтобы к ПК был подключён только он (скрипт всё равно работает по серийному номеру).
3. Проверка: `adb devices` должен показать `R5CY82VT33X   device`.

## Прогон (повторить для каждой сборки)
Условия должны быть одинаковыми для всех прогонов:
- закройте VAP из «Недавних», откройте заново, дождитесь списка папок, подождите ~5 с, не листайте;
- видео не играет, тяжёлые приложения закрыты, телефон не горячий; зарядка подключена или нет — но каждый раз
  одинаково; яркость и частоту экрана не меняйте;
- открывайте **одну и ту же папку с большим числом файлов** (50 и больше).

```bash
bash tools/perf/measure-device.sh R5CY82VT33X 30 main-A
```
Скрипт покажет данные об устройстве и установленной сборке, спросит «готов ли телефон» (Enter), и после
слова **СТАРТ** у вас 30 секунд: **6 раз** откройте папку, подождите ~2 с, вернитесь назад, подождите ~2 с.
Не листайте, не трогайте док.

Результат: `tools/perf/out/main-A-<время>/summary.txt` — пришлите его содержимое. Файл `trace.txt` (десятки МБ)
присылать не нужно, он нужен только мне при разборе.

## Сравнение «до / после»
1. Прогон **A**: на том, что стоит сейчас. В `summary.txt` раздел «какая сборка установлена» скажет, есть ли
   в ней оптимизации открытия папки (метки этапов 4/4б) и вариант `foss` или `cast`.
2. Если установлена старая сборка и вы хотите сравнить, поставьте новую **сами** (я этого не делаю):
   ```bash
   adb -s R5CY82VT33X install -r app/build/outputs/apk/foss/release/app-foss-release.apk
   ```
   Только если в `summary.txt` написано «подписи СОВПАДАЮТ» и вариант `foss`. Флаг `-r` обновляет поверх и
   сохраняет данные; при несовпадении подписи `adb` просто откажет (ничего не пропадёт). **Не удаляйте
   приложение перед установкой**: это сотрёт данные. Если у вас вариант `cast`, скажите — нужна другая сборка.
3. Прогон **B** тем же способом с меткой `main-B`.
4. По каждой сборке полезно сделать два прогона: между повторами разброс ±5 процентных пунктов.

## Как читать summary.txt
| строка | что значит | лучше |
|---|---|---|
| кадров на переход, частота в переходе | сколько кадров нарисовано за анимацию открытия или закрытия | больше |
| RenderThread: дольше 8,3 мс (%), p90, max | кадры, не уложившиеся в 120 Гц | меньше |
| дольше 16,7 мс (рендер и главный поток) | кадры, не уложившиеся в 60 Гц | меньше, в идеале 0 |
| загрузок текстур в GPU (Texture upload) | у старой сборки — сотни, у новой — единицы | меньше |
| тяжёлых кадров (>=8 проходов) | окна размытия стекла дока | меньше |
| gfxinfo: janky, перцентили кадра и GPU | сводка системы | меньше |

Заметка: у адаптивных экранов Samsung частота меняется по ходу работы, а `gfxinfo` считает «медленные кадры»
относительно текущей частоты — сравнивайте сборки между собой на одном телефоне, а не с Xiaomi.

## Если что-то не так
- «Телефон не найден»: проверьте кабель, подтвердите отладку на экране телефона, `adb kill-server`.
- В разделе «трасса» написано, что `atrace` не отработал: останется только `gfxinfo`, этого уже достаточно для
  сравнения процента медленных кадров.
- Скрипт можно проверить на тестовом Xiaomi: `YES=1 bash tools/perf/measure-device.sh 3871a9d6 20 check`.

## Превью: сколько раз кадры декодируются, читаются с диска, берутся из памяти (тестовый Xiaomi)
Метки `Trace` в `ThumbnailCache`: `VAP.thumb.mem` (кадр уже в памяти), `VAP.thumb.disk` (чтение из хранилища),
`VAP.thumb.gen` (декодирование видео и запись всех трёх размеров).
```bash
export ANDROID_SERIAL=3871a9d6 MSYS_NO_PATHCONV=1
adb shell svc power stayon true     # иначе экран гаснет посреди сценария; вернуть: svc power stayon false
bash tools/perf/scroll-folder.sh out.txt 1 "d u d" 75      # перезапуск, вниз-вверх-вниз по VAP-Perf-Huge, трасса 75 с
grep "VAP.thumb" out.txt | sed -E 's/.*(B\|[0-9]+\|VAP.thumb.[a-z]+).*/\1/' | sort | uniq -c
python tools/perf/slice_durations.py out.txt VAP.thumb.disk VAP.thumb.gen
```
Папка находится через `uiautomator dump` по `content-desc`, а не по координатам (порядок папок на главном экране меняется).
Под Git Bash у Windows-`python` нет `/tmp`: пути к файлам передавайте через `cygpath -m`.
